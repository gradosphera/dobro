# ADR 001. Local-first: статика + браузер + блокчейн

- Статус: принято
- Дата: 2026-10-22
- Контекст: защита персональных данных (152-ФЗ), политика dobro.ru п. 3.7

## Проблема

Текущий серверный вариант (`api/*` + Neon) обрабатывает и хранит
псевдонимные данные волонтёров (`volunteer_id`, кошелёк, часы) за пределами
РФ: Vercel и Neon — зарубежные площадки. Политика dobro.ru (п. 3.7)
запрещает трансграничную передачу данных граждан РФ, а согласие на это
портал не получает в рамках нашего сценария.

## Что проверено

| Источник | CORS для браузера | Вывод |
|---|---|---|
| `dobro.ru/api/v2/*` | нет `Access-Control-Allow-Origin` | браузер не может звать напрямую |
| `storage.yandexcloud.net` (vote.txt) | нет CORS | документ тоже только через прокси/снапшот |
| `tonapi.io/v2/*` | отражает `Origin`, credentials | можно звать из браузера |
| `api.ton.vote/dao/*` | `Access-Control-Allow-Origin: *` | можно звать из браузера |

Проверка:

```bash
curl -sSI -H 'Origin: https://example.com' \
  'https://dobro.ru/api/v2/organizations/10072836?with=organizer' | grep -i access-control
```

Вывод: полностью «всё в браузере» невозможно из-за CORS у dobro.ru.
Компромисс без сервера — **снапшот публичных данных**, снятый оператором
или CI. В нём нет персональных данных: только карточка организации,
отпечаток документа и параметры DAO.

## Решение

1. **Статика.** Сайт — только HTML/CSS/JS. Деплой на любой статический
   хостинг. Секретов, БД и серверных эндпоинтов у сайта нет.
2. **Снапшот dobro.ru.** `npm run snapshot -- --org <id> --dao <addr>`
   снимает публичную карточку, проверяет адрес DAO в `vote.txt`, читает
   owner/жетон и пишет `public/data/orgs/<id>.json`. Снапшот обновляется
   вручную/по cron и коммитится; браузер читает его как обычный JSON.
3. **TON — из браузера.** TON Connect подключает кошелёк; owner DAO
   сверяется с подключённым кошельком через `api.ton.vote`/`tonapi.io`.
   Подпись транзакции происходит в кошельке пользователя.
4. **Аттестация — on-chain.** Лидер отправляет перевод на **свой** адрес
   (self-transfer) с текстовым комментарием:

   ```
   dobro/att/1 o=10072836 v=95490358 p=2026-10 h=12.5 d=1be8b8a926ff0386
   ```

   `o` — организация, `v` — публичный id волонтёра, `p` — месяц, `h` —
   часы, `d` — первые 16 hex sha256 документа с адресом DAO. Комментарий
   ≤ 120 байт (лимит стандартного комментария TON — 127). Транзакция —
   одновременно подпись, запись и доказательство авторства (sender).
5. **Чтение — из браузера.** История адреса лидера читается через
   `tonapi.io` и фильтруется по префиксу. Дубликаты по
   `(org, volunteer, period)` схлопываются: побеждает транзакция с большим
   `lt`.
6. **Выплаты — офлайн.** Скрипт фонда сканирует цепочку, проверяет, что
   sender — owner DAO на момент записи, и отправляет BLG через highload
   wallet v3. Публичного сервера выплат нет.
7. **Серверный слой (`api/*`, Neon)** остаётся в репозитории как
   альтернатива/референс, но для v1 не требуется и не разворачивается.

## Поток данных

```
браузер ── fetch ──> public/data/orgs/*.json      (статика, без ПДн)
   │
   ├── fetch ──────> api.ton.vote / tonapi.io       (CORS ok)
   ├── TON Connect ─> кошелёк пользователя          (подпись локально)
   └── send ───────> TON: self-transfer + комментарий
                         │
фонд (CLI) ── scan ──────┘──> highload v3 ──> BLG волонтёру
```

## Модель доверия

- `volunteer_id` и кошелёк волонтёра вносит лидер; публичного списка
  «волонтёр → кошелёк» у dobro.ru нет. Ответственность — на owner DAO.
- Лидер не может подделать авторство: запись валидна, только если
  sender — owner DAO (проверяется по истории и текущему owner).
- Отзыв/исправление — новая запись с тем же ключом; фонд берёт последнюю
  по `lt`. Полная неизменяемость не нужна: важна проверяемая подпись.
- Снапшот доверенный на момент сборки; хэш документа фиксируется в
  аттестации, поэтому подмена снапшота ломает сверку `d`.

## Последствия

Плюсы: ПДн не покидают браузер пользователя; нет БД и серверных секретов;
аудируемость on-chain; нулевая стоимость эксплуатации сервера.

Минусы/риски:

- снапшот устаревает (часы/документы меняются) — обновлять cron'ом;
- каждая аттестация стоит комиссию сети (~0.001–0.01 TON) и требует TON
  у лидера;
- история кошелька лидера — публична (это уже свойство TON);
- запрос к статике зарубежного хостинга передаёт IP/UA за границу; для
  строгого соответствия статику тоже размещать в РФ;
- п. 7.2 правил dobro.ru запрещает автоматизированный сбор — нужно
  письменное разрешение info@dobro.ru, даже при ручном снапшоте.

## План

1. ✅ Снапшот + формат аттестации + тесты.
2. TON Connect в статике, сверка owner DAO, отправка комментария.
3. Читатель on-chain аттестаций (tonapi) и UI списка/клеймов.
4. CLI выплат highload v3 для фонда.
5. Обновление снапшота по cron + подпись снапшота ключом оператора
   (опционально, для защиты от подмены статики).

## Отклонённые альтернативы

- **CORS-прокси в РФ** — проще, но это снова сервер, логи и ПДн.
- **Публичный CORS-прокси** — недопустимо: утечка и нарушение правил.
- **Neon + Vercel** — трансграничная передача, против п. 3.7.
- **Собственный контракт-реестр** — дороже и сложнее; self-transfer с
  комментарием даёт тот же аудит без деплоя и аудита контракта.
