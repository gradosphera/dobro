# dobro-hours — сканер зарегистрированных волонтёрских часов на dobro.ru

Сервис, который по названию организации находит её на **dobro.ru** и отдаёт
**общее число зарегистрированных волонтёрских часов** из карточки
организации (вкладка «Информация» → блоки «Рейтинг» / «Результаты» / «Часы»),
а также сводку по всей платформе.

Готов к деплою на Vercel как проект типа «Other»: статика из `public/`,
serverless-функции в `api/`.

---

## 1. Технический вывод: развертывание на Vercel возможно

Vercel для этого случая подходит полностью:

| Требование | Как закрыто |
|---|---|
| Исходящие HTTP-запросы к dobro.ru | Serverless-функции Node.js делают `fetch` без ограничений |
| Статический UI | `public/index.html` отдаётся как статика проекта «Other» |
| Время ответа | 1 поисковый запрос + 5 карточек ≈ **1.5–3 с**; жёсткий внутренний бюджет 8 с |
| Холодный старт | < 1 с, состояние не требуется |
| Кэширование | TTL-кэш в памяти лямбды (`lib/cache.ts`) + `Cache-Control` заголовки |
| Стоимость | Hobby-тариф покрывает задачу (функции < 100 тыс. вызовов/сутки) |

Функции Vercel работают **вне России** (AWS), что напрямую конфликтует с
пунктом 3.7 Политики конфиденциальности dobro.ru — см. раздел 5.

## 2. Где именно лежат данные (обратная разработка API)

Все эндпоинты открытые, без авторизации — это те же самые запросы, которые
выполняет сам портал при рендере страниц.

### 2.1 Блок «Часы» конкретной организации

```http
GET https://dobro.ru/api/v2/organizations/{organization_id}?with=organizer
Accept: application/json
```

```jsonc
{
  "id": 10008257,
  "name": "НЕравнодушные сш7",
  "results": "…",                    // ← блок «Результаты» (текст организации)
  "settlement": { "shortName": "Няндома" },
  "organizer": {
    "id": 10940891,
    "statistic": {                   // ← блок «Рейтинг» и «Часы»
      "organizerRating": 5,          //    рейтинг
      "organizerRatingCount": 34,    //    число оценок
      "volunteersCount": 174,        //    волонтёров
      "volunteersWithHoursCount": 105,
      "hours": 12631,                //    «Часы» — зарегистрированные часы
      "eventsCount": 28,
      "projectsCount": 3,
      "vacanciesCount": 30
    }
  }
}
```

> Важно: без `with=organizer` блок `statistic` содержит только рейтинг.
> `hours` может быть дробным (`441244.3`) — округляем при выводе.

### 2.2 Поиск организации по названию

```http
GET https://dobro.ru/api/v2/organizers/search?query=<название>&limit=50&page=1
Accept: application/json
```

Ответ — массив организаторов. Важно: `id` в выдаче — это **id организатора**,
а `remoteId` — **id организации** (его и надо подставлять в 2.1).

```jsonc
{
  "id": 10940891,             // organizer id
  "remoteId": 10008257,       // ← organization id
  "name": "НЕравнодушные сш7",
  "fullName": "Муниципальное Бюджетное …",
  "location": { "title": "Архангельская обл, г Няндома, …" },
  "statistic": { "volunteersCount": 174, "organizerRating": 5, "organizerRatingCount": 34 }
}
```

Параметры `with=` (`organization`, `organizer`, `image`, `assistants`, …)
не дают `hours` — карточку всё равно нужно запросить отдельно.

### 2.3 Сводка по всей платформе («общее число часов»)

```http
GET https://dobro.ru/api/v2/analytics/get[?country=RU&region=72&year=2025]
```

```jsonc
{
  "statistics": {
    "hours": 274753323,        // ← общее число зарегистрированных часов
    "verifiedHours": 244036371,
    "volunteers": 10747913,
    "events": 1554720,
    "organizers": 239564,
    ...
  }
}
```

Фильтры `country` / `region` / `year` работают (например, Москва: `region=77`).

### 2.4 Места в рейтингах (нет в API)

`placeInRatings` (`{ "2026": { "all": 511, "region": 10 }, "all": {...} }`)
отдаётся **только** в серверном рендере страницы. Берётся из
`<script id="__NEXT_DATA__">` на `https://dobro.ru/organizations/{id}/info`.
Это HTML ~140 КБ, поэтому подтягивается только для трёх лидеров и только
при `?rankings=1`.

## 3. Что здесь реализовано

```
api/hours.ts     GET /api/hours?q=<название>[&limit=5][&detail=5][&rankings=1]
api/total.ts     GET /api/total[?country=RU][&region=77][&year=2025]
lib/dobro.ts     клиент dobro.ru (retry, таймауты, User-Agent, SSR-фолбэк)
lib/match.ts     нормализация и ранжирование совпадений
lib/cache.ts     TTL-кэш в памяти лямбды (с дедупликацией параллельных запросов)
public/index.html  UI
scripts/dev-server.ts     локальный эмулятор роутинга Vercel
scripts/verify-deploy.mjs сборка настоящим билдером Vercel + запуск лямбды
test/local.test.ts        16 тестов (unit + интеграция с живым dobro.ru)
test/build.test.ts        3 теста сборки под Vercel
```

### Алгоритм `/api/hours`

1. `GET /api/v2/organizers/search?query=…&limit=50` → до 50 кандидатов.
2. Локальное ранжирование по названию → 5 кандидатов на загрузку карточек.
3. Параллельно (4 одновременно) `GET /api/v2/organizations/{remoteId}?with=organizer`.
4. Повторное ранжирование с учётом числа часов.
5. Ответ: `bestMatchHours` + список организаций с `hours`, `rating`,
   `ratingCount`, `results`, `placeInRatings` (по запросу), `url` на портал.

Параметры:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `q` | — | название организации (обязательно) |
| `limit` | 5 | сколько организаций вернуть в списке (1…10) |
| `detail` | 5 | сколько карточек загрузить (1…8) — влияет на точность при омонимах |
| `rankings` | 0 | `1` — дополнительно подтянуть места в рейтингах (медленнее) |

### Устойчивость (важно для Vercel)

Функция **всегда** отвечает валидным JSON и **никогда** не выходит за лимит
времени платформы:

* общий бюджет запроса — 8 с (`BUDGET_MS`), а `maxDuration` в `vercel.json` — 10 с;
  таймаут каждого вложенного запроса обрезается по остатку бюджета, поэтому
  суммарное время функции ограничено бюджетом, а не суммой таймаутов;
* если JSON-API недоступен (защита от роботов, блокировка IP, 5xx) — карточка
  берётся из SSR-разметки `__NEXT_DATA__` страницы `/organizations/{id}/info`;
* при исчерпании бюджета возвращаются уже собранные данные с флагом
  `partial: true`, а не ошибка;
* ошибки отдаются как JSON со статусом 502 и подсказкой, а UI показывает
  человекочитаемое сообщение вместо сырого `SyntaxError`.

> Раньше (до этой правки) внутренние таймауты могли суммироваться до 36 с на
> один запрос, а деплой на Vercel отвечал HTML-страницей
> «A server error has occurred…» с HTTP 500 — фронтенд падал с
> `Unexpected token 'A', "A server e"... is not valid JSON`. Теперь платформа
> не успевает убить инстанс, а ответ всегда приходит в JSON.

### Главная причина падения `FUNCTION_INVOCATION_FAILED` (найдена и исправлена)

Билдер Vercel (`@vercel/node` v5) **не бандлит** проект: он трассирует
зависимости через `@vercel/nft` и компилирует каждый `.ts` файл по отдельности
через `ts.transpileModule`. В лямбду попадают файлы `lib/cache.js`,
`lib/dobro.js`, `lib/match.js` — а импорты в `api/hours.js` оставались вида

```js
import { cached } from '../lib/cache.ts';   // ← такого файла в лямбде нет
```

Итог — `ERR_MODULE_NOT_FOUND` при загрузке модуля, и Vercel отвечает
`500 FUNCTION_INVOCATION_FAILED` (а не наш JSON). Локально это не
воспроизводилось: dev-режим и esbuild-бандл переписывают пути, а рантайм
Vercel — нет.

Исправление — опция `rewriteRelativeImportExtensions: true` в `tsconfig.json`:
после трансляции импорты становятся `../lib/cache.js` и совпадают с файлами
в лямбде.

Проверяется без аккаунта Vercel:

```bash
npm run verify:deploy
```

Скрипт собирает проект **настоящим билдером `@vercel/node`**, выполняет
полученную лямбду так же, как рантайм Vercel (`import(pathToFileURL(...))`),
и проверяет, что `/api/hours` и `/api/total` отвечают 200. Регрессия
закреплена тестами в `test/build.test.ts`.

### Проблема омонимов и как она решена

У сетевых организаций десятки одноимённых филиалов: «Волонтеры-медики |
Москва», «Волонтеры-медики | Амурская область», … Поиск возвращает их
в произвольном порядке, а имена почти неразличимы.

`lib/match.ts` решает это так:

* название делится на **основную часть** (до `|`) и **региональный суффикс**;
* балл = `0.85 × покрытие(запрос ⊂ название + полное имя + адрес)`
  `+ 0.15 × покрытие(запрос ⊂ основная часть)` + бонус за точное совпадение
  − штраф за «лишние» слова в названии;
* при равных баллах (Δ ≤ 0.04) первым идёт **крупнейший по часам** филиал;
* город из запроса («Волонтеры-медики Москва») поднимает нужный филиал;
* в ответе есть флаг `ambiguous`, если совпадений несколько.

Проверено на живых данных: запрос «Волонтеры-медики» → лидер
«Волонтеры-медики | Санкт-Петербург» (1 412 320,9 ч), запрос
«Волонтеры-медики Москва» → «… | Москва» (441 244,3 ч), запрос
«Волонтеры-медики | Республика Дагестан» → «… | Республика Дагестан»
(742 914,4 ч).

## 4. Запуск

```bash
npm install

# локальный эмулятор Vercel (без vercel CLI и без логина)
node --experimental-strip-types scripts/dev-server.ts
curl 'http://localhost:3000/api/hours?q=Волонтеры-медики'

# тесты (включают обращения к живому dobro.ru)
npm test

# проверка типов
npx tsc --noEmit

# сборка настоящим билдером Vercel + запуск лямбды (без аккаунта)
npm run verify:deploy
```

### Деплой на Vercel

```bash
npm i -g vercel
vercel login
vercel            # preview
vercel --prod     # production
```

Репозиторий не требует настроек: `api/*.ts` станут функциями
`/api/hours` и `/api/total`, `public/index.html` — главной страницей.
После логина можно проверить боевой деплой:

```bash
curl 'https://<ваш-домен>.vercel.app/api/total'
curl 'https://<ваш-домен>.vercel.app/api/hours?q=Волонтеры-медики'
```

> В этой среде `vercel deploy` не выполнен: CLI требует авторизации
> (`vercel login`), а временные деплои без неё недоступны.
> Локальный эмулятор `scripts/dev-server.ts` повторяет роутинг Vercel
> (статика + `api/*`), все эндпоинты проверены по HTTP.

### Если деплой отвечает HTML-страницей ошибки

Симптом: вместо JSON приходит страница Vercel «A server error has occurred
while fetching the resource.» — фронтенд показывает
`Unexpected token 'A', "A server e"... is not valid JSON`.

Порядок проверки:

```bash
curl -i 'https://<ваш-домен>/api/total'                    # ожидается 200 + application/json
curl -i 'https://<ваш-домен>/api/hours?q=Волонтеры-медики'
```

* HTTP 5xx + HTML → смотрите логи функции в Vercel Dashboard → Function Logs.
  Чаще всего это превышение лимита времени (исправлено: внутренний бюджет 8 с
  против `maxDuration` 10 с) или падение при загрузке модуля.
* HTTP 404 → сборка не прошла либо каталог `api/` не распознан.
* HTTP 200, но в теле JSON поле `error` → dobro.ru не отвечает с этого IP;
  на JSON-блокировку работает SSR-фолбэк.

**5.2 Запрет на копирование контента.** Те же Правила, п. 8.5:

> целиком или по частям без предварительного разрешения правообладателя.

**5.3 Трансграничная передача ПДн.** Политика конфиденциальности
(`https://dobro.ru/privacy`), п. 3.7: Ассоциация «Добро.рф» обязуется не
допускать копирование и перенос персональных данных российских граждан на
носители, расположенные за пределами РФ. Карточки организаций содержат ФИО
руководителя и телефоны (`leader.firstName`, `leader.lastName`, `telephone`).
Vercel-функции исполняются на инфраструктуре AWS вне РФ → формально
нарушение, если эти поля покидают РФ.

**5.4 robots.txt.** Для `User-agent: *` запрещён шаблон `Disallow: /*?*`,
то есть URL с query-строкой (`/api/v2/organizers/search?query=…`,
`/organizations/{id}/info` — как раз с query) закрыты от краулеров.
robots.txt регулирует краулеров, а не API-клиентов, но это сигнал о позиции
владельца.

**5.5 Что делать перед боевым запуском**

1. Написать в **info@dobro.ru** (техподдержка организаторов, ответ 72 ч) или
   в Ассоциацию «Добро.рф» (ОГРН 1147799008851) с запросом на:
   - использование публичных эндпоинтов `/api/v2/*` в режиме «по запросу»;
   - использование имени организации, числа часов, рейтинга и ссылки на карточку.
2. Получить **письменное разрешение** (тот же канал, info@dobro.ru).
3. Ограничить выдачу: не отдавать ФИО руководителя и телефоны — поля
   `leader` и `telephone` в ответе уже не возвращаются. Остаётся проверить
   `fullName`: у ИП это полное имя физического лица, поэтому для
   чувствительных случаев его тоже стоит скрывать.
4. Не делать массовое зеркалирование: 1 пользовательский запрос → 1 поисковый
   запрос + ≤ 5 запросов карточек, с паузой и кэшем (уже реализовано).
5. Указать в интерфейсе источник и ссылку на портал (уже реализовано).
6. Разместить деплой на серверах в РФ, если письменного разрешения на
   трансграничную передачу не получено.

### Что можно сделать без разрешения

Сводку по платформе (`/api/v2/analytics/get`) портал сам публикует на
главной странице — агрегаты «Часы», «Волонтёрских часов», «Волонтёров»
показываются в блоке «Аналитика». Использование опубликованных агрегатов
существенно безопаснее, чем автоматический сбор по карточкам.

## 6. Ограничения реализации

* `hours` на портале обновляется постоянно — числа могут отличаться от снимка.
* У части организаций `hours = 0` (нет подтверждённых часов).
* `placeInRatings` требует разбора SSR-разметки и медленнее API (~+1 с).
* SSR-фолбэк (резервный путь) тянет ~140 КБ HTML на карточку.
* Кэш в памяти лямбды не общий между инстансами; для продакшена —
  `@vercel/kv` (интерфейс `lib/cache.ts` совместим).
* Поиск портала не поддерживает морфологию и опечатки: «добро» найдёт
  «ДоброЦентр», но «добр» — не найдёт ничего.
* `maxDuration` = 10 с выбран так, чтобы задеплоиться на любом тарифе Vercel
  (включая Hobby с лимитом 10 с). На Pro/Enterprise его можно поднять
  одновременно с `BUDGET_MS` в `api/hours.ts`.

## 7. Привязка организации к DAO в TON

Проверка состоит из двух независимых доказательств. Оба считаются на
сервере и не требуют доверия к клиенту.

| Слой | Что проверяется | Эндпоинт |
|---|---|---|
| **A. Криптографический** | `daoRoles.owner` DAO совпадает с кошельком из TON Connect | `GET /api/verify-owner` |
| **B. Организационный** | в публичном документе карточки организации записан адрес DAO | `GET /api/verify-org-doc` |

### 7.1 Слой A — владелец DAO

```http
GET /api/verify-owner?org=10072836&dao=EQDExlp6EjkVN-OJ1ZcGLEYlITaold5ytBP3e8g6g_BIRaZX&wallet=EQB7fbZPQ0MGHJt-hGpgAAfQT-tSXm2wMcOSzllnBs-zA3jz
```

```jsonc
{
  "ok": true,
  "verdict": "owner",              // owner | proposalOwner | none | unknown
  "org": { "id": 10072836, "name": "КГОО \"ГРАДОСФЕРА\"", "verified": true, "hours": 924.5 },
  "dao": {
    "address": "EQDEx…",
    "daoId": 85,
    "owner": "EQB7fbZ…",
    "proposalOwner": "EQB7fbZ…",
    "jetton": "EQBlary…",
    "dns": "gradosphera.ton",
    "terms": null
  },
  "checks": { "orgVerified": true, "walletIsOwner": true, "walletIsProposalOwner": true }
}
```

* `ok` = организация верифицирована на dobro.ru **и** (если передан `wallet`)
  кошелёк — `owner` DAO.
* `verdict = proposalOwner` даёт право создавать предложения, но **не**
  менять метаданные DAO: `SetMetadata` принимает только `owner`.
* Адреса сравниваются по raw-представлению, поэтому `EQ…`/`UQ…`/`0:hex`
  одного адреса эквивалентны.
* Источник состояния — публичный `https://api.ton.vote/dao/{address}`.
  `owner` может смениться, поэтому ответ кэшируется на 60 с.

### 7.2 Слой B — документ организации

```http
GET /api/verify-org-doc?org=10072836&dao=EQDExlp6EjkVN-OJ1ZcGLEYlITaold5ytBP3e8g6g_BIRaZX
```

```jsonc
{
  "ok": true,
  "found": true,
  "document": { "name": "vote.txt", "size": 49, "sha256": "1be8b8a9…", "status": "match" },
  "addresses": ["EQDEx…"],
  "checks": { "orgVerified": true, "docsAvailable": true, "docFound": true }
}
```

* Сервис читает `docs[]` из `GET /api/v2/organizations/{id}?with=organizer`,
  скачивает только текстовые файлы (`.txt`, `.md`, `.json`), не больше
  64 КБ, только с `storage.yandexcloud.net` и `dobro.ru` (https), с общим
  бюджетом 7 с. PDF/PPT не парсятся — да, `vote.txt` и есть штатный формат.
* `sha256` считается по исходным байтам файла и служит отпечатком
  доказательства: его можно сохранить в БД и показывать пользователю.
* Порядок сканирования: `vote.txt` → остальные текстовые файлы по размеру,
  максимум 5 попыток.

### 7.3 Тесты

```bash
node --experimental-strip-types --test test/verify.test.ts
```

Тесты ходят в реальные `api.ton.vote` и `dobro.ru` и проверяют референсную
пару: организация 10072836 ↔ DAO 85 ↔ `vote.txt` ↔ owner.

## 8. База данных (Neon Postgres)

Без `DATABASE_URL` сервис работает в режиме только-чтения: слои A/B
функционируют, а эндпоинты с записью отвечают `503`. Это позволяет
задеплоить проект до подключения базы.

```bash
# 1. Подключить Neon: Vercel → Storage → Neon (переменная DATABASE_URL
#    или POSTGRES_URL появится автоматически), либо локально:
export DATABASE_URL='postgres://…'

# 2. Создать таблицы
npm run db:migrate
```

Схема — `db/schema.sql`:

| Таблица | Назначение |
|---|---|
| `organizations` | привязка `org_id` ↔ `dao_address` ↔ `jetton_address` + отпечаток документа |
| `members` | волонтёр (`volunteer_id`) ↔ кошелёк, роль (`leader`/`volunteer`), статус |
| `attestations` | заявленные часы за месяц: `period_month`, `hours`, статус, кто подтвердил |
| `claims` | начисление BLG: `amount`, `query_id`, `tx_hash`, статус выплаты |

Персональные данные (ФИО, email, телефон) не хранятся: только публичные
числовые id dobro.ru, TON-адреса и часы. Это осознанное ограничение под
п. 3.7 политики конфиденциальности портала.

## 9. Вход по кошельку (TON Connect `ton_proof`)

Три эндпоинта, сервер ничего не хранит (stateless):

```http
POST /api/auth-challenge   { "wallet": "EQ…" }
  -> { "payload": "v1.…", "wallet": "EQ…", "expiresAt": "…" }

POST /api/auth-verify
  { "address": "EQ…",
    "proof": { "timestamp": 1730000000, "domain": "example.com",
               "payload": "v1.…", "signature": "<base64>" } }
  -> { "token": "v1.…", "wallet": "EQ…", "expiresAt": "…" }

GET /api/auth-me            Authorization: Bearer <token>
  -> { "wallet": "EQ…", "expiresAt": "…" }
```

* `payload` из challenge передаётся в `tonConnectUI.connectWallet({ tonProof })`.
* Сервер проверяет `ton_proof` по спецификации TON Connect:
  `sha256(0xffff + "ton-connect" + sha256("ton-proof-item-v2/" + workchain +
  hash + domainLen + domain + timestamp + payload))`.
* Публичный ключ берётся **из контракта кошелька** (`get_public_key` через
  tonapi), а не из тела запроса — иначе подпись подделывается.
* Домен сверяется с `AUTH_DOMAIN` (список через запятую) или `Host`.
  Timestamp — окно ±5 минут.
* Challenge и сессия — HMAC-SHA256 токены на `AUTH_SECRET` (≥16 символов).
  Без `AUTH_SECRET` auth-эндпоинты отвечают `503`, остальной сервис работает.
* Ограничение stateless-схемы: challenge нельзя погасить досрочно; окно
  повтора ограничено временем жизни challenge (10 мин) и timestamp-проверкой.

Переменные окружения: `AUTH_SECRET` (обязательна для auth),
`AUTH_DOMAIN` (например, `dobro.example.com`), `TONAPI_KEY` (опционально,
повышает лимиты tonapi).
